# ADD DISCORD-BASED AI PROVIDER CONFIGURATION

Tambahkan kemampuan untuk mengatur konfigurasi AI Core langsung melalui Discord.

Tujuan utama:

Saya ingin dapat menambahkan, mengganti, menghapus, dan mengetes API key AI melalui Discord tanpa harus masuk ke Replit setiap kali API key diganti.

Sistem ini harus terintegrasi dengan AI Core yang sudah ada.

JANGAN menghapus AI Core yang sudah ada.

JANGAN menghapus Project Knowledge.

JANGAN menghapus Error Analyzer.

JANGAN menghapus Investigation.

JANGAN menghapus Code Analysis.

JANGAN menghapus Vision Analysis.

JANGAN menghapus Fix Generator.

JANGAN menghapus konfigurasi AI yang sudah ada.

Audit terlebih dahulu struktur project yang sudah ada dan gunakan sistem konfigurasi/database yang sudah tersedia jika memungkinkan.

==================================================
3. CHANGE API KEY VIA DISCORD MODAL
==================================================

Saat owner menekan:

🔑 Change API Key

Buka Discord Modal.

Modal:

🔐 UPDATE AI API KEY

Masukkan API key baru:

[ Secure Input ]

⚠️ API key harus diproses secara aman.

JANGAN meminta user mengirim API key melalui chat biasa.

JANGAN menggunakan command seperti:

/setapikey sk-proj-xxxxxxxx

Karena API key dapat tersimpan di message history, audit log, cache, atau log lainnya.

Gunakan Discord Modal atau mekanisme input privat yang paling aman yang didukung oleh Discord.

==================================================
4. API KEY SECURITY
==================================================

API key adalah data rahasia.

Aturan wajib:

1. Jangan pernah menampilkan API key lengkap di Discord.
2. Jangan pernah menulis API key ke console log.
3. Jangan pernah menulis API key ke error log.
4. Jangan pernah menulis API key ke AI analysis.
5. Jangan pernah memasukkan API key ke Project Knowledge.
6. Jangan pernah menyimpan API key di source code.
7. Jangan pernah mengirim API key ke channel Discord.
8. Jangan menyimpan API key sebagai plaintext jika sistem storage mendukung enkripsi.
9. Batasi akses konfigurasi hanya kepada user yang memiliki izin.
10. Jangan membocorkan API key dalam error message.

Tampilan API key harus selalu disensor:

sk-proj-••••••••••••

atau:

Configured
Last 4:
••••1234

Jangan pernah menampilkan seluruh API key.

==================================================
5. VALIDATE API KEY BEFORE SAVING
==================================================

Saat owner memasukkan API key baru:

1. Terima input secara aman.
2. Validasi format dasar.
3. Lakukan test connection ke provider.
4. Jika valid:
   - Simpan secara aman.
   - Aktifkan provider.
   - Reload AI Core provider.
   - Jangan restart seluruh bot jika tidak diperlukan.
5. Jika tidak valid:
   - Jangan menyimpan key.
   - Tampilkan error yang aman.
   - Jangan menampilkan API key yang dimasukkan.

Contoh sukses:

✅ AI API KEY UPDATED

Provider:
OpenAI

Status:
🟢 Connected

Model:
gpt-5.4-mini

API Key:
Configured

AI Core:
🟢 ONLINE

Contoh gagal:

❌ API KEY VALIDATION FAILED

Provider:
OpenAI

Status:
🔴 Connection failed

Reason:
Provider rejected the credentials or connection failed.

Jangan tampilkan API key.

==================================================
6. PERSISTENCE
==================================================

Konfigurasi API key harus tetap tersedia setelah bot restart.

Jangan hanya menyimpan key di RAM.

Gunakan storage persistent yang sudah tersedia di project jika memungkinkan.

Alur:

Discord Modal
↓
Validate API Key
↓
Secure Storage
↓
AI Core Runtime Configuration
↓
Bot Restart
↓
Load Secure Configuration
↓
AI Core ONLINE

Jika project sudah memiliki database atau secure configuration system, gunakan sistem tersebut.

Jangan membuat database baru jika sistem lama dapat digunakan.

==================================================
7. ENCRYPTION
==================================================

Jika API key disimpan ke database atau storage:

- Jangan menyimpan plaintext jika dapat dihindari.
- Gunakan encryption at rest jika memungkinkan.
- Encryption key tidak boleh disimpan bersama ciphertext secara tidak aman.
- Jangan hardcode encryption key di source code.

Jika deployment environment menyediakan secure secret storage, gunakan mekanisme tersebut jika memungkinkan.

Audit kemampuan storage yang tersedia sebelum implementasi.

==================================================
8. ENVIRONMENT VARIABLE FALLBACK
==================================================

Pertahankan dukungan untuk:

OPENAI_API_KEY

Prioritas konfigurasi:

1. Secure runtime configuration dari AI Core
2. Secure persistent configuration
3. Environment variable OPENAI_API_KEY sebagai fallback

Contoh:

Runtime AI Config
↓
Jika tersedia → gunakan runtime config

Jika tidak tersedia:

Secure Persistent Config
↓
Jika tersedia → gunakan persistent config

Jika tidak tersedia:

OPENAI_API_KEY
↓
Gunakan environment variable

Jika tidak ada:

AI Core masuk mode fallback/local.

Jangan merusak konfigurasi environment yang sudah ada.

==================================================
11. CHANGE MODEL
==================================================

Tambahkan pengaturan model melalui AI Configuration.

Contoh:

🧠 SELECT AI MODEL

Model:
gpt-5.4-mini

Jika provider/API menolak model:

- Tampilkan error yang aman.
- Jangan menghapus konfigurasi yang masih valid.
- Jangan mengganti model secara otomatis tanpa persetujuan.
- Tampilkan model yang tersedia jika dapat diketahui dari provider.

Jangan mengasumsikan model tersedia jika belum divalidasi.

==================================================
12. REMOVE API KEY
==================================================

Tambahkan:

🗑️ Remove API Key

Harus ada confirmation:

⚠️ REMOVE AI API KEY?

Jika dihapus:

- Hapus konfigurasi runtime.
- Hapus konfigurasi persistent sesuai storage.
- Jangan menghapus Project Knowledge.
- Jangan menghapus AI Core.
- Jangan menghapus channel configuration.
- Jangan menghapus error history.

Setelah dihapus:

Provider:
🔴 NOT CONFIGURED

AI Core tetap berjalan dalam fallback/local mode jika sistem tersebut sudah ada.

==================================================
13. ACCESS CONTROL
==================================================

Hanya user yang memiliki akses AI Core Configuration yang dapat:

- Mengganti API key.
- Menghapus API key.
- Mengubah provider.
- Mengubah model.
- Mengubah AI configuration.

Default:

👑 Owner Only

Jangan izinkan user publik mengubah konfigurasi.

Jangan izinkan user biasa mengakses secret.

==================================================
14. DISCORD SECURITY
==================================================

API key input harus:

- Diproses melalui Modal atau private interaction.
- Tidak dikirim sebagai public message.
- Tidak masuk ke channel history.
- Tidak masuk ke bot log.
- Tidak masuk ke AI log.
- Tidak masuk ke error embed.
- Tidak masuk ke Project Knowledge.

Jika Discord interaction memiliki data sensitif, hapus atau minimalkan data tersebut setelah diproses jika memungkinkan.

↓

Jangan menyebabkan duplicate listeners atau duplicate AI clients.

OpenAI

- Invalid API key
- Expired/revoked key
- Rate limit
- Model unavailable
- Network error
- Provider outage
- Timeout
